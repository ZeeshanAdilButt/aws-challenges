# Datasets

Small files, generated by a script with a fixed **seed**. A seed is a starting number for a random number generator: the same seed gives the same file on every computer. Everything in them is made up. Names, keys and addresses are invented, and addresses come from the ranges the internet standards keep for examples (`192.0.2.0/24`, `198.51.100.0/24`, `203.0.113.0/24`).

Everything in them is made up; prices in the usage reports are the dated prices of `toolkit/prices.js` and the research notes.

To make them again (the usage reports: run the challenge 15 part 1 script): `node datasets/make-access-log.mjs` and `node datasets/make-cloudtrail-log.mjs`. The result must be identical (git shows no change).

## daftar-api-access-log.jsonl

What the Daftar API role did for 14 days from 2026-10-12: one JSON object per line with `time`, `principal`, `action`, `resource` and `context`. Eight kinds of call (reading and writing notes in S3, sending jobs to a queue, reading and writing sessions in DynamoDB, one secret read, log writes), weighted like a real API: about half of the calls are `s3:GetObject`.

## cloudtrail-leaked-key.jsonl

A week of events in the shape of AWS CloudTrail (`eventTime`, `eventSource`, `eventName`, `awsRegion`, `sourceIPAddress`, `userAgent`, `userIdentity`, `requestParameters`, `errorCode`). It holds normal work by two people, a CI user and nine API task sessions, and one leaked key: the CI user's key is used by a stranger from `192.0.2.77` on 2026-10-19. The file is not a copy of any real log.

`cloudtrail-leaked-key.facts.json` records what the generator injected, counted inside the generator. The challenge 3 tests compare your answers with it.
